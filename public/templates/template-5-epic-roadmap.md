## Epic quality check

Run every epic through these checks before you create it in GitLab.

1. Does it touch more than one part of the product (repo map)? If not, it is probably a milestone.

2. Does it name the person it helps (persona) and the journey step it fixes?

3. Is there ONE measure that tells us it worked?

4. Does 'Out of scope' say something real that people might expect?

5. Are the dependencies written, including other products and other teams?

6. Did I write it myself, with no AI, and can I explain it out loud?

7. Does the order on the roadmap have a reason I can say in one sentence?

HOW THIS MAPS TO GITLAB: create each epic in your product group; paste Title, Description (Problem... Risks), Start date, Due date and Labels; use Parent epic for hierarchy; link milestones and issues after the epic exists; then open the Roadmap view and compare it with the 'Roadmap grid' sheet.
