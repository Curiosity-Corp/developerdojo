Education · Pathway

From a learning page to a checked accessibility report.

Four katas on web accessibility for learning material, on an openly licensed Wikibooks chapter and the W3C’s WCAG 2.2 and ACT rules. Each step has a file you can open and a result that CI computes again on every pipeline.

Start with EDU-001Open the report

01 / The files

One textbook page, rules checked first, every result rerun

The page is the Wikibooks chapter “High School Mathematics Extensions/Matrices” (revision 266672), saved exactly as Wikibooks served it to a reader: 177.9 kB of HTML. WCAG 2.2 states the success criteria, and the W3C’s ACT rules state exactly how to test parts of them, each with published test cases and their expected outcomes. The script checks its rules against those test cases before it looks at the page.

  • The page (HTML): Wikibooks’ file, unchanged, CC BY-SA 4.0.
  • The W3C test case index with the 36 approved test cases used, and the IANA Language Subtag Registry (File-Date 2026-11-18).
  • The page inspection, the rule outcomes and the WCAG report (JSON).
  • The result summary (Markdown) and every result under the manifest, with the method and every input hash.
  • The pathway script (Python 3.12, standard library only, MIT), so you can rerun every result yourself.
  • README: sources, terms, how to rerun the checks, and what they do not cover.

02 / The steps

Four katas, in order

Each kata has a brief, prompts, checks and the evidence for the checks the Dojo has run. They are drafts: the Dojo built the example and CI checks it, and no learner has run them yet. Do the foundations first: Compare AI instructions and Spot a context trap.

  1. EDU-001 Inspect a learning page

    Read an open textbook page as a reader’s browser receives it: its title, language, viewport, headings, images, links and tables.

  2. EDU-002 Run accessibility rules

    Build four W3C ACT rules, check them against every approved W3C test case, then run them on the page.

  3. EDU-003 Report against WCAG 2.2

    Map each rule outcome to its success criterion, and write down what the rules leave untested.

  4. EDU-R01 Education Randori: an unseen change

    A partner reveals one change to the page after you start; predict which rule and criterion move, then recompute.

The page (EDU-001)

Title: “High School Mathematics Extensions/Matrices - Wikibooks, open books for an open world”. Language en, direction ltr, viewport width=1120. 16 headings (1 h1, 6 h2, 8 h3, 1 h4), with no level skipped; 26 images, 24 with alternative text, 2 with an empty one (marked decorative) and 0 without; 155 links; 2 tables, 0 with a caption. The counts say what is there, not whether it is right: that needs a person. Result (JSON).

04 / The tools and sources

No packages, public sources

The script uses only the Python 3.12 standard library, so it runs offline with nothing to install. Any browser opens the page, and any text editor shows its source. The Armory lists the stack recipe Python standard library.

  • Web Content Accessibility Guidelines (WCAG) 2.2, W3C Recommendation, 12 December 2024: success criteria 1.4.4 Resize text, 2.4.2 Page Titled and 3.1.1 Language of Page.
  • W3C ACT Rules: 2779a5 HTML page has non-empty title, b5c3f8 HTML page has lang attribute, bf051a HTML page lang attribute has valid language tag and b4f0c3 Meta viewport allows for zoom, with their outcome mapping, and their test cases.
  • IANA Language Subtag Registry, File-Date 2026-11-18: the language subtags that make a known primary language tag.
  • Why it matters in education: in the United States, 28 CFR 35.200 requires state and local government entities, which include public schools and universities, to make their web content meet WCAG 2.1 Level A and AA from 26 April 2027 or 26 April 2028, depending on their size. The three criteria checked here are in WCAG 2.0, 2.1 and 2.2.

05 / What is checked

Verified, and not verified

Verified

  • The page is the one Wikibooks served, unchanged (SHA-256 c42e87b501ee…, checked by the site’s tests).
  • Before it checks the page, the script runs its four rules on each of the W3C’s published test cases for them and gives all 36 their published outcome (2779a5, b5c3f8, bf051a and b4f0c3), and refuses to write any result if one differs. (evidence)
  • On the page, rule 2779a5 is passed, b5c3f8 passed, bf051a passed and b4f0c3 inapplicable; by the rules’ outcome mapping, WCAG 2.2 criteria 1.4.4, 2.4.2 and 3.1.1 all need further testing and none is shown not satisfied. (evidence)
  • On every pipeline, CI reruns the script with Python 3.12 and fails if any output differs from the files on this page. (evidence)

Not verified

  • Any conformance or legal compliance. Nothing here says that the page, a course or a site conforms to WCAG 2.2 or 2.1, or meets 28 CFR 35.200 or any other law.
  • Every other WCAG success criterion, including alternative text (1.1.1), headings and tables (1.3.1) and contrast (1.4.3): the inspection counts images and headings but judges none.
  • The page after its scripts run, rendered in a browser, zoomed or read by assistive technology.
  • Rules that need a person: whether the title describes the page (c4a8a4) and whether lang matches the text (ucwvc8).
  • Use by real learners: no learner has run these katas yet, and no learner’s data is used.

Professional review: None. No digital accessibility specialist, assistive technology user or education accessibility compliance reviewer has reviewed this pathway; a real course or site needs a full evaluation against every success criterion.

What this field adds to the shared foundations

Every sector pathway follows the same template: the field's own terms and procedures, the standards its work is read against, the files it produces, belt criteria, and the qualified review a real use needs. The katas build on the shared foundations and do not repeat them.

Terms of the field

Success criterion
A testable statement in WCAG, with a level (A, AA or AAA), such as 2.4.2 Page Titled; conformance at a level means meeting every criterion of that level and below.
ACT rule
A W3C Accessibility Conformance Testing rule: it states exactly which elements it applies to and what it expects of them, so two tools give the same outcome on the same page.
Applicability and test target
The part of a page a rule applies to; each element it applies to is a test target with its own outcome.
Outcome
Passed, failed or inapplicable (or cantTell): what a rule concludes for a page. Inapplicable means nothing on the page matched the rule, not that the page passed.
Outcome mapping
How a rule’s outcome bears on its success criterion: any failed outcome means the criterion is not satisfied; passed and inapplicable leave further testing to do.
Language tag and primary language subtag
The value of lang, such as en or fr-CA; its first part, looked up in the IANA Language Subtag Registry, names the language.
Open educational resource
Learning material under an open licence, such as this CC BY-SA textbook chapter, that anyone may copy, check and adapt with attribution.

Procedures practised

  1. Inspect a learning page’s title, language, viewport, headings, images and tables before judging it (EDU-001)
  2. Run accessibility rules that first give the W3C’s published test cases their expected outcome (EDU-002)
  3. Report rule outcomes against WCAG 2.2 by the outcome mapping, naming what was not tested (EDU-003)
