Robotics · Pathway

From an open robot model to a checked pose and joint solution.

Four katas on the open UR5 robot description, in simulation. Each step has a file you can open and a result that CI computes again on every pipeline. Nothing here moves a real robot or is a safety assessment.

Start with ROB-001Download the poses

01 / The files

One open robot model, every number rerun

The Universal Robots ROS 2 Description publishes the kinematics of the UR5 arm as a small file: where each of its six joints sits on the link before it. Robot software computes every pose from numbers like these. The script first reproduces every value the Modern Robotics code library prints in its worked examples and checks the file against the manufacturer’s DH table, then computes poses and joint solutions for configurations and targets the Dojo wrote.

Simulation only. No real robot moved. Nothing on this page is a risk assessment, a safety function or a check against a robot safety standard, and no robot cell should be planned from it. Never send these joint angles to a real arm.

  • The UR5 kinematics file (YAML) and its licence: the Universal Robots ROS 2 Description’s files, unchanged.
  • Five joint configurations and three target poses with their initial guesses (CSV).
  • The poses (CSV), the same with the agreement of the three methods and the joint solutions (JSON).
  • The model inspection and the reference checks (JSON).
  • The result summary (Markdown) and every result under the manifest, with the method and the input hashes.
  • The pathway script (Python 3.12, standard library only, MIT), so you can rerun every number yourself.
  • README: sources, terms, how to rerun the checks, and what they do not cover.

02 / The steps

Four katas, in order

Each kata has a brief, prompts, checks and the evidence for the checks the Dojo has run. They are drafts: the Dojo built the example and CI checks it, and no learner has run them yet. Do the foundations first: Compare AI instructions and Spot a context trap. The robot software track goes on to ROS 2 and simulators.

  1. ROB-001 Inspect a robot model

    Read the UR5’s open description entry by entry: units, conventions, which numbers are the manufacturer’s DH lengths, and what the file does not hold.

  2. ROB-002 Forward kinematics three ways

    Reproduce the Modern Robotics code library’s worked examples, then compute five poses by the joint chain, the DH table and the product of exponentials, and find the singular ones.

  3. ROB-003 Inverse kinematics, checked

    Find joint angles for target poses by Newton-Raphson, check each by the joint chain, and report a target out of reach as no solution.

  4. ROB-R01 Robotics Randori: an unseen change

    A partner reveals one changed assumption after you start; predict what moves and by how much, then recompute.

03 / The checks

Reproduce the published examples, then compute

These results come from CI: the pipeline reruns /examples/robotics-pathway/tools/robotics_pathway.py and fails if any output differs from the published files.

Reference checks: the library’s worked examples

188 of 188 values printed in the worked examples of 12 functions (Adjoint, FKinBody, FKinSpace, IKinBody, IKinSpace, JacobianBody, JacobianSpace, MatrixExp3, MatrixExp6, MatrixLog3, MatrixLog6, TransInv) are reproduced when rounded as printed. The script stops without writing any result if one differs. Every value (JSON).

The model (ROB-001)

Lengths in metres and angles in radians, the units REP 103 sets for ROS; the file states no units of its own. Each entry is a URDF joint origin: x, y, z translate, then roll, pitch, yaw rotate about the fixed x, y and z axes (R = Rz(yaw) Ry(pitch) Rx(roll)); each joint then turns about its own z axis. Frames are right-handed (REP 103).

The methods are the file’s joint chain, the manufacturer’s DH table and the product of exponentials with screw axes read from the file; they share no code beyond matrix products. Where the determinant of the Jacobian is zero the arm is singular: stretched out, straight up, or with the wrist straight so that two joint axes line up. Result (JSON), poses (CSV).

04 / The tools and sources

No packages, open sources

Six joints need only small matrices, so the script uses only the Python 3.12 standard library and runs offline with nothing to install. The Armory lists the stack recipe Python standard library.

  • Universal Robots ROS 2 Description: the UR5 kinematics file, pinned to a commit, BSD-3-Clause.
  • Universal Robots, DH parameters for calculations of kinematics and dynamics, read on 27 November 2026: the UR5 table, cited for its numbers.
  • The code library of Modern Robotics: Mechanics, Planning, and Control (Cambridge University Press, 2017), MIT licence: the worked examples in its docstrings, cited for their printed values. Its code is not copied.
  • REP 103, Standard Units of Measure and Coordinate Conventions: metres, radians, right-handed frames and fixed-axis roll, pitch and yaw.
  • ISO 10218-1 and ISO 10218-2, the safety standards for industrial robots and their integration, are named only: their text was not read, and nothing here is checked against them.

05 / What is checked

Verified, and not verified

Verified

  • The UR5 file and its licence are the Universal Robots ROS 2 Description’s files, unchanged (SHA-256 4559bd027c93…, checked by the site’s tests).
  • The script reproduces all 188 values printed in the worked examples of 12 functions of the Modern Robotics code library, and 6 of 6 DH lengths of the file equal Universal Robots’ table; it writes no result if one differs. (evidence)
  • At 5 joint configurations the joint chain, the DH table and the product of exponentials agree within 2.9e-10 m, and every joint solution the solver finds puts the arm on its target when checked by the joint chain; the target 1.208 m from the shoulder gets no solution. (evidence)
  • On every pipeline, CI reruns the script with Python 3.12 and fails if any output differs from the files on this page. (evidence)

Not verified

  • Any real robot, cell or application. Nothing here is a risk assessment, a safety function or a check against a robot safety standard; ISO 10218-1 and ISO 10218-2 are named, not read or checked.
  • Joint limits, collisions, velocities, dynamics, payload and any tool: the poses are of the last link of the nominal model.
  • A calibrated arm, whose own kinematics differ from the nominal file.
  • All solutions of the inverse kinematics: the solver finds one near its initial guess, and the UR5 has up to eight.
  • Use by real learners: no learner has run these katas yet.

Professional review: None. No robotics safety engineer, controls engineer or robot integrator has reviewed this pathway; it is simulation only, and anything on real hardware needs a risk assessment by qualified people under the standards that apply.

The field template

What this field adds to the shared foundations

Every sector pathway follows the same template: the field's own terms and procedures, the standards its work is read against, the files it produces, belt criteria, and the qualified review a real use needs. The katas build on the shared foundations and do not repeat them.

Terms of the field

Joint origin
Where a joint sits on the link before it, as x, y, z in metres and roll, pitch, yaw in radians; the URDF chains them from the base to the last link.
Forward kinematics
From joint angles to the pose of the end of the arm: its position and orientation in the base frame.
Inverse kinematics
From a target pose back to joint angles. There can be several solutions, or none when the target is out of reach.
DH parameters
The Denavit-Hartenberg table: four numbers a, d, alpha and theta per joint that describe the same chain in a fixed convention, as manufacturers publish it.
Screw axis
A joint’s axis of motion as a twist (w, v), from which the product of exponentials composes the pose without per-link frames.
Jacobian
How joint speeds become end-effector speeds. Where its determinant is zero the arm is singular: it loses a direction of motion and the solver loses its step.
REP 103
The ROS convention for units and frames: metres, radians, right-handed axes and roll, pitch and yaw about the fixed x, y and z axes.

Procedures practised

  1. Inspect a robot model: units, conventions, the DH lengths and what the file does not hold, before using it (ROB-001)
  2. Compute forward kinematics three independent ways and find the singular configurations (ROB-002)
  3. Solve inverse kinematics by Newton-Raphson and check every solution by another method (ROB-003)
