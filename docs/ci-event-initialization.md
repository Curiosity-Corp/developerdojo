# Investigate event-schema initialization in CI

Issue #122 tracks intermittent timeouts in the first valid event parse. The normal test suite and its timeout remain unchanged. `scripts/diagnose-event-initialization.mjs` is an optional diagnostic that runs inside a CI job with the project's Node version and installed dependencies. It must not replace or gate the existing unit tests.

Run `node scripts/diagnose-event-initialization.mjs` in a GitLab CI job after `npm ci` and retain `event-initialization-diagnostic.json` as an artifact, including on failure. Each sample uses a new Node process and fictional fixture. The script runs the real `eventsSchema.safeParse` and, separately, an `Intl.DateTimeFormat` construction for UTC and Asia/Manila. It records the first call and five repeated calls, worker process and import time, monotonic wall time, process CPU time, and optional cgroup v2 quota and CPU-throttling counters. It alternates batches with one or three concurrent children for three rounds. A timed-out child is recorded as a failure rather than silently omitted.

Compare first and repeated calls within the same child, then compare independent children and configurations. Cgroup deltas describe the entire job cgroup over each measurement interval; concurrent samples overlap and are not independent per-process throttling measurements. Unavailable files or counters are `null`, not zero. Shared-runner load, cache state and scheduling can change during a run. Capture multiple runs, runner load and relevant job concurrency before drawing a conclusion; an isolated diagnostic does not reproduce the exact failing conditions by itself. If the schema-only path is slow but Intl is not, investigate the rest of schema initialization too. These measurements do not prove why a test timed out or measure user-facing performance.

To avoid obscuring the issue, do not increase timeouts, silently retry, remove assertions, treat a single fast run as a fix, or run synthetic load against shared infrastructure without an appropriate test environment. Report sample count, errors, conditions and limitations with any proposed fix.
